# SongNest 设计文档

> 版本：v0.1（阶段 1）　状态：草案，开发中可调整

## 1. 目标

做一个能「添加到主屏幕」的 iPhone 音乐应用：从「文件」App 导入本地音乐，按歌单整理和播放。数据只保存在手机本地，不需要服务器，也不需要账号。

**目标设备**：iPhone，iOS 16 及以上，使用 Safari 添加到主屏幕后运行。电脑浏览器只用于开发调试。

## 2. 功能范围

### MVP（必须做）

| # | 功能 | 说明 | 阶段 |
|---|---|---|---|
| F1 | 导入音乐 | 从「文件」App 一次选多首，保存到本地 | 3 |
| F2 | 歌曲库 | 显示所有已导入的歌曲：标题、歌手、时长、封面 | 4 |
| F3 | 播放 | 播放/暂停、拖动进度条、显示当前时间 | 4 |
| F4 | 歌单增删改 | 新建、重命名、删除歌单 | 5 |
| F5 | 歌单内容 | 向歌单添加或移除歌曲，调整顺序 | 5 |
| F6 | 播放队列 | 上一首/下一首，播完自动接下一首 | 6 |
| F7 | 播放模式 | 顺序播放、随机播放、单曲循环 | 6 |
| F8 | 锁屏控制 | 锁屏界面显示歌名、封面和控制按钮 | 7 |
| F9 | 可安装、离线 | 能添加到主屏幕，断网也能打开 | 8 |

### 以后再做（阶段 10）
从歌曲库删除歌曲、搜索、显示存储空间占用、数据备份和恢复、深色模式。

### 不做
在线音乐、账号和云同步、读取「音乐」App 的曲库、编辑歌曲标签、歌词。

## 3. 页面结构

用 hash 路由（`#/library` 这种形式）。这是纯前端实现，GitHub Pages 不需要额外配置。

| 路由 | 页面 |
|---|---|
| `#/library` | 歌曲库（默认首页） |
| `#/playlists` | 歌单列表 |
| `#/playlist/<id>` | 歌单详情 |

底部播放条和标签栏在所有页面上都显示。点播放条会展开全屏播放页（阶段 6 做）。

## 4. 视觉风格：温暖柔和

关键词：**奶油色、暖橙、白色卡片、小圆角**。整体要像一个温馨的「小窝」，但又不能显得幼稚。

### 4.1 颜色

所有颜色都定义成 CSS 变量，写在 `styles/main.css` 的 `:root` 里，代码中不直接写色值。深色模式跟随手机设置（`prefers-color-scheme: dark`）自动切换。

| 变量 | 用途 | 浅色 | 深色 |
|---|---|---|---|
| `--bg` | 页面背景 | `#FBF6EE` 奶油色 | `#1F1A16` 暖深棕 |
| `--card` | 歌曲行、歌单卡片 | `#FFFFFF` | `#2B241F` |
| `--card-2` | 播放条、输入框、按下状态 | `#F3E6D3` | `#352C25` |
| `--border` | 分隔线（尽量少用） | `#EADFCF` | `#3A312A` |
| `--text` | 主要文字 | `#3B2F25` | `#F3EAE0` |
| `--text-2` | 次要文字：歌手、时长 | `#7D6A58` | `#A8998A` |
| `--accent` | 主按钮的底色 | `#E8913A` | `#E8913A` |
| `--on-accent` | 主按钮上的文字 | `#2E1D0C` | `#2E1D0C` |
| `--accent-text` | 选中的标签、播放图标、文字链接 | `#A85A15` | `#F0A75C` |
| `--danger` | 删除等危险操作 | `#B3452F` | `#E07A62` |

**可读性规则**：文字和背景的对比度至少要达到 4.5:1（WCAG AA 标准）。所以浅色模式下的次要文字和强调文字，都比样稿里的颜色稍微加深了一点。橙色按钮上用深棕色文字，因为白字放在橙色上不够清楚。

**没有封面的歌曲**：用三种暖色（`#F6D9B8`、`#E6D3C6`、`#D8E3CF`，深色模式下是 `#5A4330`、`#4D3E38`、`#3E4A38`）中的一种做底色，中间放一个音符图标。具体用哪种颜色由歌曲 id 计算得出，所以同一首歌每次显示的颜色都一样。

### 4.2 圆角

| 元素 | 圆角 |
|---|---|
| 歌曲行、歌单卡片 | 8px |
| 列表中的封面 | 6px |
| 播放条中的小封面 | 4px |
| 按钮、输入框 | 6px |
| 播放条 | 10px |
| 弹窗、底部弹出菜单 | 12px |
| 全屏播放页的大封面 | 10px |

不用胶囊形（全圆角），也不用圆形封面。

### 4.3 文字

- 字体：系统字体 `-apple-system, "PingFang SC", "Helvetica Neue", sans-serif`。iPhone 上会显示为苹方和 San Francisco，不需要额外下载字体
- 只用两种字重：常规 400、加粗 600

| 层级 | 字号 | 字重 | 例子 |
|---|---|---|---|
| 页面标题 | 28px | 600 | 「歌曲库」 |
| 区块标题 | 20px | 600 | 全屏播放页的歌名 |
| 正文 | 16px | 400 | 歌名 |
| 次要 | 13px | 400 | 歌手、时长、歌曲数量 |
| 标签栏 | 11px | 400 | 「歌曲库」「歌单」 |

### 4.4 间距与尺寸

- 间距只用这几档：4 / 8 / 12 / 16 / 24 px
- 页面左右留白 16px，歌曲行之间间隔 6px
- **所有能点的东西，点击区域至少 44×44 px**（苹果的建议），图标再小也要留够点击范围
- 适配刘海屏和底部横条：用 `env(safe-area-inset-*)` 给顶部和底部留出空间

### 4.5 图标

使用 [Tabler Icons](https://tabler.io/icons)（MIT 开源许可）的线条风格，24px，线宽 1.75。把用到的几个图标的 SVG 直接复制进代码，不从网上加载，这样离线也能显示。

### 4.6 动效

- 按下时：背景变成 `--card-2`，并缩小到 0.98 倍，持续 120ms
- 页面切换、弹出菜单：200ms，`ease-out`
- 不做花哨的动画。如果用户在手机上开了「减弱动态效果」，就关闭所有动画

## 5. 主要流程

**导入**：点「导入」→ 系统弹出「文件」App 并选择多首歌 → 逐个读取元数据（读不到就用文件名做标题，歌手显示「未知歌手」）→ 存入数据库 → 列表刷新，提示「已导入 N 首」。

**播放**：点某首歌 → 把当前列表（歌曲库或歌单）作为播放队列，从这首开始播放。

**添加到歌单**：点歌曲的 `⋯` → 选「添加到歌单」→ 选一个歌单，或者新建一个。

## 6. 数据模型（IndexedDB）

数据库名 `songnest`，版本 1。音频文件和元数据**分开存**：显示列表时只读取元数据，播放时才读取音频文件。

### `songs`：歌曲元数据（主键 `id`）
```js
{
  id: "uuid",            // crypto.randomUUID()
  title: "晴天",
  artist: "周杰伦",       // 读不到时为 null，界面显示「未知歌手」
  album: "叶惠美",        // 可为 null
  duration: 269.5,       // 秒
  cover: Blob | null,    // 嵌入在音频文件里的封面
  fileName: "qingtian.mp3",
  fileSize: 10834212,    // 字节
  fileKey: "qingtian.mp3|10834212", // fileName + "|" + fileSize，用来识别重复导入
  mimeType: "audio/mpeg",
  addedAt: 1730956800000 // 时间戳（毫秒）
}
```
索引：`addedAt`（排序用），`fileKey`（唯一索引，判断是否重复导入）。

### `audio`：音频文件（主键 `id`，和 `songs.id` 一致）
```js
{ id: "uuid", blob: Blob }
```

### `playlists`：歌单（主键 `id`）
```js
{
  id: "uuid",
  name: "通勤",
  songIds: ["uuid1", "uuid2"], // 数组顺序就是播放顺序
  createdAt: 1730956800000,
  updatedAt: 1730956800000
}
```

### 规则
- 同一首歌在一个歌单里只能出现一次
- 删除歌单不会删除歌曲
- 从歌曲库删除一首歌时（阶段 10），同时把它从所有歌单里移除
- 播放器的界面偏好（播放模式、音量）存在 `localStorage` 里

## 7. 代码结构（计划）

```
SongNest/
├── index.html
├── manifest.json            # 阶段 8
├── sw.js                    # Service Worker，阶段 8
├── icons/                   # 应用图标，阶段 8
├── styles/
│   └── main.css
├── js/
│   ├── app.js               # 入口：初始化、路由
│   ├── router.js            # hash 路由
│   ├── db.js                # IndexedDB 封装（只有这个文件直接操作数据库）
│   ├── importer.js          # 文件导入流程
│   ├── metadata.js          # 从音频字节里读标题、歌手、封面、时长（纯函数）
│   ├── ui.js                # 共用小工具：转义、时长格式、封面、提示条
│   ├── icons.js             # SVG 图标
│   ├── player.js            # 播放器和播放队列（只有这个文件操作 <audio>）
│   ├── player-bar.js        # 底部播放条：播放/暂停、下一首、进度条
│   ├── dialogs.js           # 弹窗：底部菜单、输入框、确认框、选歌列表
│   ├── playlist-actions.js  # 「新建歌单」「添加到歌单」流程（多个页面共用）
│   ├── media-session.js     # 锁屏控制
│   └── views/
│       ├── library.js
│       ├── playlists.js
│       └── playlist-detail.js
├── scripts/serve.mjs        # 本地预览服务器（npm run dev）
├── tests/                   # 单元测试（npm test）
└── docs/
    └── design.md
```

目前没有任何第三方库。

**分层原则**：界面（views）不直接操作数据库或 `<audio>`，统一通过 `db.js` 和 `player.js` 提供的函数来做。模块之间通过自定义事件通知变化（比如 `player:change`、`library:change`）。

## 8. iOS 限制与对策

| 限制 | 对策 |
|---|---|
| 音频必须由用户点击触发才能播放 | 只在点击事件里调用 `audio.play()`，不在页面加载时自动播放 |
| Service Worker 需要 HTTPS | 手机通过局域网 IP 预览时只测界面和播放；离线功能部署到 GitHub Pages 后再测 |
| 「文件」App 选出的文件只能临时访问 | 选完立即把内容存进 IndexedDB |
| 只在 Safari 网页里使用时，数据可能被系统清理 | 引导用户添加到主屏幕使用（主屏幕应用的数据不会被自动清理） |
| 从主屏幕删除应用会删掉所有数据 | 阶段 10 做导出备份；首次使用时给出提示 |
| 后台自动切下一首偶尔不稳定 | 阶段 7 在真机上测试，必要时用 Media Session 补救 |
| 支持的格式 | 支持 mp3、m4a/aac、wav、flac；ogg 不保证，导入时提示不支持 |

## 9. 已决定的事项

- **元数据读取**（阶段 3）：自己写解析器 `js/metadata.js`，不用 `jsmediatags`。原因：
  1. iOS 在用户没点播放时，往往不会加载音频信息，所以**时长**也必须从文件字节里直接算出来，而 `jsmediatags` 不提供时长
  2. `jsmediatags` 已经不再维护
  3. 不依赖第三方库，离线可用，代码也能完整读懂
  
  支持 MP3（ID3v2.2/2.3/2.4、ID3v1，包括 GBK 编码的中文标签）、M4A、FLAC、WAV。实在读不出时长时，退回让浏览器加载（最多等 5 秒），仍然失败就先留空。
- **封面**（阶段 3）：导入时缩小到最长边 300px，转成 JPEG（质量 0.85），一张大约几 KB 到几十 KB
- **重复导入**：文件名和大小都相同就跳过，并在提示里说明
- **iOS 播放解锁**（阶段 4）：点歌时要先从数据库读文件，读完时「点击的那一刻」已经过去，iOS 会拦截播放。所以点击时先用同一个 `<audio>` 播一段 0.1 秒静音来「解锁」它，之后再换成真正的歌曲
- **播完自动下一首**（阶段 4 提前做了）：放完队列最后一首就停下。上一首、随机、循环留到阶段 6
- **时长修正**：播放时如果浏览器给出的真实时长和导入时算的差 1 秒以上，用真实值更新数据库
- **弹窗**（阶段 5）：用浏览器自带的 `<dialog>` 元素，自带半透明背景、Esc 关闭和焦点管理，不需要第三方库
- **调整歌单顺序**（阶段 5）：用「上移 / 下移」箭头，而不是拖动。拖动排序在手机上要处理触摸、滚动冲突，代码复杂很多，以后有需要再改
- **新建歌单后**直接进入这个歌单，方便马上加歌；歌单名最长 40 个字，允许重名
- **歌单封面**：用歌单里第一首有封面的歌的封面
- **随机播放按钮**（阶段 5 先做了简单版）：把歌单打乱后从头播放。阶段 6 再做真正的「随机模式」
- **播放模式**（阶段 6）：和常见音乐软件一样，用**一个按钮**在 4 种模式间循环切换，默认是「列表循环」，选择会被记住：

  | 模式 | 图标 | 一首放完后 | 点「下一首」 |
  |---|---|---|---|
  | 列表循环（默认） | 🔁 | 下一首；最后一首之后回到第一首 | 下一首，到头回到第一首 |
  | 单曲循环 | 🔂 | 重新播放这一首 | 照常切到下一首 |
  | 随机播放 | 🔀 | 随机下一首，一轮放完后重新打乱，一直放下去 | 随机下一首 |
  | 顺序播放 | → | 下一首；最后一首之后停下 | 下一首，到最后一首时不能再点 |

  切换顺序：列表循环 → 单曲循环 → 随机播放 → 顺序播放 → 列表循环……每次切换会弹出提示，告诉你当前是什么模式。
- **上一首**：如果当前歌已经放了 3 秒以上，先回到这首歌的开头；否则切到上一首。随机模式下回到「刚才放过的那首」
- 模式按钮和上一首按钮放在**全屏播放页**（点底部播放条打开），底部播放条空间小，只保留播放/暂停和下一首
